서로 다른 int 배열의 앞 10,000칸과 100,000칸을 복사한 시간

Apple M4 Pro, Docker의 Linux aarch64, Temurin 25.0.5+8, JMH 1.37.
자바 파일은 macOS의 javac 25.0.4.1에서 --release 25로 컴파일했다.
각 배열의 용량은 두 조건 모두 100,000칸이다. 10,000 또는 100,000은 복사 길이다.
JMH가 독립 JVM 세 개를 띄웠다(길이별 세 개). JVM당 한 스레드에서 1초씩 세 번
워밍업한 뒤 1초씩 다섯 번 측정했다. 한 번의 연산은 System.arraycopy 한 번이다.
JMH가 반환된 목적지 배열을 소비한다. 각 반복의 시작에서 목적지 전체를 0으로
초기화하고 끝에서 복사된 앞부분과 손대지 않은 나머지까지 확인한다.
두 단계와 배열 할당은 측정 구간 밖에서 실행한다.

재현 명령 (CopyLengthBench.java를 빈 디렉터리에 복사한 뒤 실행)

mkdir -p lib classes
repo=https://repo.maven.apache.org/maven2
for artifact in \
  org/openjdk/jmh/jmh-core/1.37/jmh-core-1.37.jar \
  org/openjdk/jmh/jmh-generator-annprocess/1.37/jmh-generator-annprocess-1.37.jar \
  net/sf/jopt-simple/jopt-simple/5.0.4/jopt-simple-5.0.4.jar \
  org/apache/commons/commons-math3/3.6.1/commons-math3-3.6.1.jar
do
  curl -fLsS --max-time 60 "$repo/$artifact" -o "lib/${artifact##*/}" || exit 1
done
javac --release 25 -cp 'lib/*' \
  -processorpath 'lib/jmh-core-1.37.jar:lib/jmh-generator-annprocess-1.37.jar' \
  -processor org.openjdk.jmh.generators.BenchmarkProcessor -d classes CopyLengthBench.java
image=eclipse-temurin@sha256:ecdc0adb37bde1a281c4d245a3cd535004b1fc8322d560f5b09463b248c81df0
docker run --rm --network=none --platform linux/arm64 -v "$PWD:/bench" -w /bench "$image" \
  java -cp 'classes:lib/*' org.openjdk.jmh.Main '^bench.CopyLengthBench.copy$' \
  -t 1 -jvmArgs '-Xms256m -Xmx256m' -rf json -rff results.json

평균 비율 20.12배 (10만 칸 평균 / 1만 칸 평균).
JMH 표의 Error는 99.9% 신뢰구간 반폭이다. 각 fork에서 측정한 평균을 따로 실었다.

같은 배열을 반복 사용했으므로 작업 대상 메모리가 캐시에 남을 수 있다.
독립적인 목적지, 유효한 범위, 성공한 int[] 복사에 대한 두 길이의 측정이다.
두 점의 시간 비율은 배열 복사의 점근 복잡도를 증명하거나 특정 캐시의 영향을
식별하지 못한다. 한 번의 호출이 복사하는 논리적 데이터 양은 4 × count 바이트다.
