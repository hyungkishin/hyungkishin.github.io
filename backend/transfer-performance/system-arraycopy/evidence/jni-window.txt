JMH 1.37, Apple M4 Pro, Linux ARM64 (Docker), Temurin 25.0.5+8, 단일 측정 스레드.
jdk25 헤더와 GCC 14.3.1로 C 라이브러리를 빌드했다. JMH 측정 조건별 새 JVM 3개, JVM마다
0.5초 워밍업 2회와 0.5초 측정 3회. JMH Error는 99.9% 신뢰구간의 반폭이다. 이 수치는
고정된 두 배열에서 단순 복사를 하거나 명시한 범위의 블록을 순회한 결과다.

재현: JniCopyBench.java, CopyWindowBench.java, copybench.c를 빈 폴더에 넣는다.
다음 명령은 호스트 Temurin javac 25와 Docker를 사용한다. Python 3는 결과 JSON 확인에만 필요하다.

mkdir -p lib classes native
repo=https://repo.maven.apache.org/maven2
for artifact in \
  org/openjdk/jmh/jmh-core/1.37/jmh-core-1.37.jar \
  org/openjdk/jmh/jmh-generator-annprocess/1.37/jmh-generator-annprocess-1.37.jar \
  net/sf/jopt-simple/jopt-simple/5.0.4/jopt-simple-5.0.4.jar \
  org/apache/commons/commons-math3/3.6.1/commons-math3-3.6.1.jar
do
  curl -fLsS --max-time 60 "$repo/$artifact" -o "lib/${artifact##*/}" || exit 1
done
javac --release 25 -h native -cp 'lib/*' -processorpath 'lib/jmh-core-1.37.jar:lib/jmh-generator-annprocess-1.37.jar' \
  -processor org.openjdk.jmh.generators.BenchmarkProcessor -d classes JniCopyBench.java CopyWindowBench.java
builder=ghcr.io/graalvm/native-image-community@sha256:0d936f32bb8acb5bc60c41b33e05f064d7a6aaf36b726538296c54949bd4a3c0
docker run --rm --network=none --platform linux/arm64 --entrypoint sh -v "$PWD:/bench" -w /bench "$builder" \
  -ec 'gcc -O2 -Wall -Werror -shared -fPIC -I native -I "$JAVA_HOME/include" -I "$JAVA_HOME/include/linux" copybench.c -o libcopybench.so'
image=eclipse-temurin@sha256:ecdc0adb37bde1a281c4d245a3cd535004b1fc8322d560f5b09463b248c81df0
runbench() { docker run --rm --network=none --platform linux/arm64 -v "$PWD:/bench" -w /bench "$image" "$@"; }
runbench java --enable-native-access=ALL-UNNAMED -Djava.library.path=/bench -cp 'classes:lib/*' bench.JniCopyBench
runbench java -cp 'classes:lib/*' org.openjdk.jmh.Main 'bench.(JniCopyBench.(intrinsic|jniElements|jniRegions)|CopyWindowBench.copy)$' \
  -t 1 -foe true -jvmArgs '-Xms512m -Xmx512m --enable-native-access=ALL-UNNAMED -Djava.library.path=/bench' -rf json -rff native-window.json
runbench java -cp 'classes:lib/*' org.openjdk.jmh.Main 'bench.JniCopyBench.CallOnly.*' \
  -t 1 -foe true -jvmArgs '-Xms512m -Xmx512m --enable-native-access=ALL-UNNAMED -Djava.library.path=/bench' -rf json -rff boundary.json

배열 chunk는 양쪽에 같은 범위를 사용하며 37칸씩 이동한다. 슬롯 수가 2의 거듭제곱이어서 매 주기
모든 범위를 돈다. 같은 목표 원소를 1,024개 복사한다. 8 KiB, 2 MiB, 128 MiB는 양 배열에서
만지는 입력+출력 데이터의 합이며, 슬롯 수에 상관없이 복사당 출력은 4 KiB다.
호스트 CPU perflevel0 L1D=128 KiB, L2=16 MiB, perflevel1 L1D=64 KiB, L2=4 MiB
(sysctl hw.perflevel{0,1}.{l1dcachesize,l2cachesize}). 게스트 vCPU의 매 실행 코어,
실제 적중 수준과 하드웨어 카운터는 측정하지 않았다.
