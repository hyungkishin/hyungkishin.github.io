송금 한 건으로 읽는 백엔드

성능 측정과 JVM에서 송금 확정, 메시지 전달, 데이터 접근까지

연재 5편

시리즈 목차

  1. 01

    송금 버튼을 누른 뒤 사라진 시간

    송금 버튼을 누른 뒤 사용자가 기다린 시간과 서버가 기록한 응답 시간은 어디서 갈라질까. 측정 구간과 부하 조건을 정한다.

  2. 02

    같은 자바 코드가 실행 중에 달라지는 이유

    같은 수수료 호출에 정률과 정액 정책을 넣었다. 바이트코드의 호출 위치와 HotSpot 로그를 맞춰 인라인된 메서드를 확인한다.

  3. 03

    송금 성공을 언제 약속할 것인가

    송금 요청을 받았을 때와 잔액 변경이 확정됐을 때의 응답을 구분하고, 재시도로 같은 송금이 두 번 실행되는 경로를 살폈다.

  4. 04

    Kafka와 Redis가 맡는 일과 잃을 수 있는 데이터

    송금 이벤트가 다시 도착하거나 캐시 값이 뒤처졌을 때 Kafka와 Redis에서 각각 지켜야 할 조건을 정리했다.

  5. 05

    송금 내역 한 페이지가 DB를 여러 번 왕복할 때

    송금 목록에서 계좌 이름을 읽는 가상의 예제로 JPA가 보낼 SQL과 DB 왕복 횟수를 비교한다.
